# zcode 额度看板

**只看智谱 API Key 的 coding plan 额度。**

zcode 界面只显示 token plan，不显示 API Key 的额度——这个工具补上这一块：
从本机 zcode 直接读出你配的 API Key，查它们的额度、用量窗口与刷新倒计时。

**全栈 Rust**：`eframe/egui` 原生桌面界面 + `tokio` 后台运行时，无浏览器、无外部服务。
单个可执行文件，数据全部存在本地。

---

## 核心能力

### 1. 从本机 zcode 一键导入（零手动录入）

你电脑上装着 zcode 的话，**完全不用手动填 key**。点右上角「从本机 zcode 导入」，
程序只读一个文件：

| 文件 | 提取内容 |
| --- | --- |
| `~/.zcode/v2/provider_config.json` | 各 provider 的 `config.access.apiKey`（明文），即 zcode 里配的 `BigModel API` ~ `API 5` |

> 只读这一个文件，其他一概不碰：`credentials.json` 的值是 `enc:v1:` 密文且多为过期 JWT/OAuth，
> `config.json` 的 key 与之重复且也常过期——两者都只会产生噪音，索性不读。

> 整个过程**只读**，不会改动 zcode 的任何文件。
> 想确认扫到了什么，跑 `zcode-board.exe --scan-debug`（不启动界面，只打印结果）。
> 想验证桌面提醒（声音 / 归属 / 弹横幅），跑 `zcode-board.exe --test-notify`（只起托盘发一条测试气泡）。
> zcode 数据目录默认 `~/.zcode`，可用环境变量 `ZCODE_HOME` 覆盖。

### 2. 查不到额度的 key 会被明确区分

同一个 zcode 里配的多个 key，查额度的能力可能完全不同。工具会如实显示，不混淆：

| 探测结果 | 徽章 | 含义 |
| --- | --- | --- |
| `正常` | 绿点 | 拿到了额度窗口数据 |
| `无 coding plan` | 灰点 | 上游明确返回「当前用户不存在 coding plan」。**这不是故障**，说明该 key 不订阅 coding plan，没有额度可看。界面给中性提示，不进错误统计 |
| `异常` | 红叉 | 网络失败、401/403、响应无法解析等真实故障 |
| `限流冷却` | 黄箭头 | 上游 429，冷却期内跳过不再硬打 |

实测本机数据：`BigModel API`（第 1 个）返回「不存在 coding plan」，而 `BigModel API 2~5`
都能查到 `月度调用窗口 184/4000`、`5 小时 Token 窗口` 及按模型的用量明细
（search-prime 141 / web-reader 43 / zread 0）。

### 3. 疑似同一账户自动识别 + 一键合并

zcode 里配的多个 key 往往属于同一个账号（例如 API 2/3/4/5 返回完全相同的额度）。
当多个账户的配额快照**完全一致**（窗口类型、单位、用量、百分比都相同）时，
界面顶部会出现蓝色提示横幅，一键即可合并成一个账户卡片。

> 比对**故意不纳入绝对时间戳**：不同 key 的请求时刻相差几毫秒，滚动窗口的
> `nextResetTime` 就会不同，但那不代表它们属于不同账户。
> 合并后可随时在 key 行用「移到…」解除固定重新拆分。

> **与阿里云无关**：本工具只调 `api.z.ai` 的额度查询接口，纯 API Key 通路，不需要验证码或浏览器。
> 设置里的「附加请求头」是可留空的高级选项，一般用不到。

### 4. 可调节的定时刷新

- 「设置 → 定时刷新」里开关自动刷新，间隔可精确到秒（提供 30s / 1m / 5m / 15m 快捷档）；
- 并发探测数、请求超时都可调；
- **改动立即生效**，不用重启；
- 被 429 限流的 key 自动进入冷却，冷却期内跳过不去硬打；「无 plan」不重试、不冷却；
- 界面有「立即刷新」按钮，按账户 / 按 key 单独刷新也支持。

### 5. 下一次刷新时间可视化 + 提前提醒

- 每个账户卡片上，每个配额窗口都显示**刷新倒计时**（`HH:MM:SS`，接近时变红）；
- 窗口时间进度条 + 用量百分比进度条双轨显示，一眼看出是「用得快」还是「时间没到」；
- 顶栏有全局的「下一次额度刷新」和「下一次自动刷新」倒计时；
- 提醒提前量可调（1–120 分钟），命中时**桌面系统通知 + 界面顶部横幅 + 事件日志**三重送达；
- 单个账户可独立静音；设置里有「发送测试通知」验证系统通知是否可用。

### 6. 实时消耗速率 + 区间趋势图

每个配额窗口下方都有「速率区」，回答「我现在烧得有多快、这一段有没有变化」：

- **当前速率**：以最近一次刷新为锚、向前回溯一段时间的平均消耗差分
  （默认 60s 刷新回看约 5 分钟），有数值用量的窗口按原始值
  （Token 窗口 `tok/min`、调用窗口 `次/min`）；
  上游只给百分比的窗口（实测 5 小时 Token 窗口正是如此）按百分比差分，
  以 `%/h` 展示并用至少 10 分钟的平滑基准抵抗整数百分比的量化台阶；
  数值用中文习惯格式化（`2.3万` / `1.2亿`）；
- **速率曲线**：顶栏可选回看区间（30m / 1h / 6h / 24h / 全部，选择持久化），
  每次刷新向右长一个点；面积折线 + 峰值虚线，**悬停可读任意时刻的速率**；
- **区间峰均**：所选区间内逐次刷新的瞬时速率最高值与平均值；
- **预计用满**：剩余量 ÷ 当前速率的线性外推（重置先到时不显示，避免无意义的倒计时）。

速率计算的三条硬规则（在 `core::rate`，全部有单测覆盖）：

- 窗口重置产生的用量回落不是「负速率」，差分链在重置处断开；
- 相邻采样间隔 < 5s 视为量化噪声跳过；> 30 分钟视为离线间隙（含窗口在内的
  平均值不再代表瞬时）同样跳过；
- 采样按 key 归档（`data/history.json`，最多每序列 1000 条 / 保留 7 天，
  节流落盘），key 换账户、程序重启曲线都不断档；百分比序列在档案里加
  `#pct` 后缀与数值序列隔离，两种量纲永不相混。

> 数值与百分比都没有的窗口（上游完全不给信号）才不显示该区；
> 刚导入的 key 需要积累两个采样点（两次刷新）起图。

### 7. 条目管理：删除、去重、一键清理

- **重复导入无害**：同一 secret 只会保留一条，重复导入自动跳过（导入弹窗里会标注「已导入」）；
- **整卡删除**：账户卡片头部垃圾桶按钮，连它下面的所有 key 一起删，有二次确认；
- **一键清理失效条目**：导入弹窗会列出「本机 zcode 里已不存在」的同步 key（比如早期版本的残留），
  一键删掉并回收腾空的账户；手动添加的 key 不受影响；
- **启动自愈**：每次打开自动去重、回收空账户、清掉废弃来源的历史残留，只跑一次。

### 8. 托盘常驻 + 开机启动

- **右下角常驻**：程序运行时任务栏通知区有图标（绿=全部正常 / 黄=有待探测 / 红=有异常），
  悬停显示「N 个账户 · M 个 key」与下次刷新倒计时；
- **单击托盘图标**恢复窗口；**右键菜单**可直接退出程序；
- **点右上角 ✕ 默认收进托盘**（程序继续后台跑），不会再误关；
- **开机自动启动**：设置里开关，默认开（写入 `HKCU\...\Run`，值名 `zcode-board`），
  设置面板会实时显示注册表实际状态，写入失败会变色提示；
- 托盘图标注册失败时设置面板会给出 ⚠ 提示，此时关窗=退出，不会出现「窗口消失却找不到」的情况。

## 运行

```powershell
# 开发模式
cargo run --release

# 数据目录默认是 exe 所在目录下的 data/（跟随程序，不随启动位置变化），
# 可用环境变量 ZCODE_DATA_DIR 覆盖
$env:ZCODE_DATA_DIR = "D:\zcode-data"; cargo run --release
```

打开后点右上角「从本机 zcode 导入」即可自动同步；也可以点「添加 key」手动粘贴，
每行一个 API Key，支持 `备注: Key` 的写法方便区分：

```
家庭号: 0fae35...
公司号: 96aa83...
```

## 界面说明

| 区域 | 内容 |
| --- | --- |
| 顶栏 | 账户/key 统计、立即刷新、从本机 zcode 导入、添加 key、设置与日志开关，两个全局倒计时与速率回看区间切换 |
| 提醒横幅 | 有账户进入提前提醒窗口时自动出现，列出各账户剩余时间 |
| 疑似同账户横幅 | 多个账户额度数据完全一致时出现，提供一键合并与忽略 |
| 账户卡片 | 账户名（可改名）、合并的 key 数、状态、各配额窗口进度、用量数字与刷新倒计时；每个窗口下有速率区（当前速率 / 峰均 / 预计用满 / 区间速率曲线）；头部垃圾桶按钮可整卡删除（连同其下所有 key） |
| key 行 | 展开账户后可见：脱敏凭证、状态、错误信息、上次探测时间、启用/停用、删除、移到其他账户 |
| 右侧设置 | 定时刷新、下一次刷新提醒、账户归组、窗口与启动、上游接口五组配置 |
| 托盘图标 | 常驻通知区：单击恢复窗口，右键退出；悬停显示账户/key 数与刷新倒计时 |
| 底部日志 | 探测失败与通知事件 |

状态图例（彩色徽章）：正常 / 无 plan / 待探测 / 异常 / 冷却 / 已停用。
用量进度条颜色按 <60% 绿、60–85% 黄、≥85% 红 分级。

## 数据与隐私

- 全部数据存在 `data/state.json`（原子写入，损坏会自动备份为 `.json.bak` 后重置）。
  `data` 目录默认在 exe 旁边（`target/release/data`），从任何位置双击/开机启动都读同一份；
- 速率采样历史单独存 `data/history.json`（紧凑 JSON、最多每分钟落盘一次），
  与账号数据互不影响，损坏时只重置曲线、不动其他状态；
- **载入时自动迁移**：重复 secret 去重、回收空账户（幽灵卡片）、清掉早期版本遗留的
  非 API key 来源条目（JWT / OAuth / config.json 那几轮写的）， migrations 只跑一次；
- API Key / JWT **明文存在本地文件**里，请注意保护好 `data` 目录，不要把它提交到 Git；
- 界面上凭证全程脱敏显示（`前6位…后4位`）。
- 从 zcode 导入只是**读** `~/.zcode/v2/*.json`，不会写回或修改 zcode 的任何文件。

## 已知限制

- 手动添加的 key 会各自独立成户，可用「疑似同一账户」的一键合并，或用「移到…」手动合并；
- 窗口时长按 `unit` 推断（3 → 5 小时，6 → 7 天，5 → 月度）。上游若新增窗口类型，
  时间进度条会缺失，但百分比、用量数字与刷新倒计时仍正常；
- 本地扫描依赖 zcode 当前版本的存储格式（v2 目录下的 JSON）。zcode 升级改动格式后，
  扫描会扫不到东西——此时用 `--scan-debug` 看警告，退回手动添加即可。
- 「疑似同一账户」是**基于额度数据一致的启发式判断**，理论上存在误判可能
  （两个不同账户恰好额度相同）。合并前请确认，误合了可以用「移到…」解除固定重新拆分。
- 托盘与开机启动基于 Windows 通知区 / 注册表 Run 项：若系统禁用了通知区图标
  （部分企业镜像或精简系统）或组策略禁用了 Run 自启动，对应功能会失效——
  设置面板会如实显示注册表状态，托盘失败也会有 ⚠ 提示，程序主功能不受影响。
